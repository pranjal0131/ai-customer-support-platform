# SupportIQ model card

## Intended use

SupportIQ assists trained support operators with initial routing, prioritization, summarization, related-case discovery, and response drafting. It is not designed to autonomously close tickets, make financial decisions, authenticate customers, or send a response without review.

## Model components

| Component | Production artifact | Development fallback |
|---|---|---|
| Intent | best validated Banking77 classifier | keyword match |
| Sentiment | DistilBERT trained on TweetEval sentiment | bounded lexical score |
| Urgency | reviewed-label classifier when available | deterministic weak rules |
| Summary | optional FLAN-T5-small | redacted first sentences |
| Retrieval | normalized MiniLM embeddings in FAISS | local token cosine over stored tickets |
| Response | retrieved-context template | intent/sentiment template |

The health endpoint states which component is active. Demo confidence is a deterministic presentation score, not a calibrated probability.

## Evaluation

Classification scripts write accuracy, macro precision, macro recall, and macro F1 only after evaluating an actual run. Confusion matrices are stored separately. The application never ships seeded benchmark results. Compare domain slices and calibrate confidence before production use.

Urgency labels generated by `weak_label_urgency` are synthetic supervision. Performance against held-out weak labels only shows how well a model imitates those rules. It does not establish correctness or safety.

## Known failure modes

- Banking77 labels may force out-of-domain tickets into a plausible but wrong banking category.
- Negation, sarcasm, mixed sentiment, multilingual text, and long threads challenge the fallback logic.
- Urgency keywords can over-escalate quoted text or under-escalate indirect descriptions of harm.
- Extractive summaries can omit a later constraint; generative summaries can hallucinate details.
- Similar text does not guarantee that a historical resolution remains correct under current policy.
- Confidence values may be misinterpreted unless calibrated and paired with abstention rules.

## Required controls

- Clearly disclose AI assistance and require agent review.
- Redact secrets and sensitive fields before modeling and logging.
- Enforce tenant boundaries in storage and retrieval.
- Log model version, input provenance, prediction, agent edits, and final disposition.
- Monitor drift, escalation misses, category confusion, factuality, bias, and PII leakage.
- Provide a rapid model rollback and a rules-only safe mode.
